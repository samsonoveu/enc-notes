# project-vibe

REST API-сервер на Node.js, TypeScript и Express.

## Возможности

- Строгий TypeScript (`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`).
- Валидация окружения и входных данных через [Zod](https://zod.dev).
- Структурное логирование через [pino](https://getpino.io) (pretty-вывод в dev, JSON в prod).
- Централизованная обработка ошибок с единым форматом ответа.
- Сборка через [tsup](https://tsup.egoist.dev), тесты через [Vitest](https://vitest.dev) + [supertest](https://github.com/ladjs/supertest).
- ESLint 9 (flat config) + Prettier.
- Веб-интерфейс заметок с шифрованием на стороне браузера (AES-256-GCM).

## Требования

- Node.js >= 20.11.0

## Установка

```bash
npm install
cp .env.example .env
```

## Эндпоинты

| Метод    | Путь             | Описание                                 |
| -------- | ---------------- | ---------------------------------------- |
| `GET`    | `/api/health`    | Статус, uptime и версия                  |
| `GET`    | `/api/ready`     | Готовность сервиса                       |
| `GET`    | `/api/notes`     | Список заметок (только заголовки и даты) |
| `GET`    | `/api/notes/:id` | Заметка вместе с шифротекстом            |
| `POST`   | `/api/notes`     | Создание заметки (`201`)                 |
| `PUT`    | `/api/notes/:id` | Обновление заметки                       |
| `DELETE` | `/api/notes/:id` | Удаление (`204`)                         |

### Примеры

```bash
curl http://127.0.0.1:3000/api/health

curl -X POST http://127.0.0.1:3000/api/notes \
  -H 'Content-Type: application/json' \
  -d '{"title":"Список покупок","cipher":"…","salt":"…","iv":"…"}'
```

Тело заметки передаётся уже зашифрованным — см. раздел ниже.

### Формат ответа

Успешный ответ оборачивается в `data`, у списков есть `meta`:

```json
{
  "data": [{ "id": "…", "title": "Написать README", "description": null, "completed": false }],
  "meta": { "count": 1 }
}
```

Ошибки единообразны; при провале валидации добавляется `details`:

```json
{
  "error": {
    "code": "BAD_REQUEST",
    "message": "Invalid request body",
    "details": [{ "path": "title", "message": "String must contain at least 1 character(s)" }]
  }
}
```

Коды: `BAD_REQUEST` (400), `NOT_FOUND` (404), `CONFLICT` (409), `UNPROCESSABLE_ENTITY` (422), `INTERNAL_ERROR` (500).

## Заметки и шифрование

Веб-интерфейс открывается на `/`. Тело заметки шифруется **в браузере**, сервер
хранит только шифротекст и параметры для его расшифровки — пароль на сервер не
попадает никогда.

| Что          | Где хранится                                   |
| ------------ | ---------------------------------------------- |
| Пароль       | нигде, только в памяти вкладки на время сессии |
| Тело заметки | шифротекст в `NOTES_FILE`                      |
| Заголовок    | открытым текстом (нужен для списка без пароля) |

Схема:

1. Из пароля выводится ключ: PBKDF2-SHA256, 600 000 итераций, случайная соль 16 байт на каждую заметку.
2. Тело шифруется AES-256-GCM со случайным IV 12 байт; соль и IV хранятся рядом с шифротекстом.
3. При открытии заметки браузер запрашивает пароль и расшифровывает текст локально.

Проверочного значения пароля не хранится: неверный пароль проявляется как ошибка
аутентификации тега GCM, поэтому отличить его от повреждённых данных нельзя — обе
ситуации сообщаются как «Неверный пароль или заметка повреждена».

Заголовок остаётся открытым сознательно: иначе список нельзя отрисовать до ввода
пароля. Если это неприемлемо, заголовок нужно шифровать тем же ключом, а список
строить по расшифрованным на клиенте заголовкам.

> **Важно.** WebCrypto доступен только в защищённом контексте. `localhost` и
> `127.0.0.1` считаются таковыми, а открытие по обычному HTTP с IP в локальной
> сети (например, с телефона) — нет: страница покажет ошибку. Для проверки с
> мобильного нужен HTTPS или туннель.

## Структура

```
src/
  app.ts                     сборка Express-приложения (без listen)
  index.ts                   точка входа: listen, graceful shutdown
  config/env.ts              схема и загрузка окружения
  lib/                       HttpError, логгер, валидация
  middleware/error-handler.ts обработка 404 и ошибок
  modules/notes/             схема, файловый репозиторий, роутер заметок
  routes/health.routes.ts    health/ready
public/                      веб-клиент (отдаётся как статика, без сборки)
  index.html                 разметка экранов: список, чтение, редактор
  styles.css                 минималистичный mobile-first дизайн
  app.js                     логика интерфейса и вызовы API
  crypto.js                  PBKDF2 + AES-256-GCM через WebCrypto
tests/                       тесты конфига, ошибок, репозитория, API и шифрования
```

Хранилище заметок — файл на диске (`NoteRepository`), переживает перезапуск.
Для продакшена достаточно заменить репозиторий на реализацию с БД: маршруты
зависят от интерфейса, а не от хранилища.
